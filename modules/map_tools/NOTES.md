# map_tools module notes

Extensions for the game's own full-screen map (`MapUI`). Module key `map_tools`, on by default (every feature has its own switch; the defaults change nothing but the extra icons). Options tab: HUD > Full Map. Game 1.3.0; everything is resolved by name, the RVAs below are only for re-checking after an update (Cpp2IL dump + IDA, `re/dump/`).

## Map open detection

`MapUI.LateUpdate` (0x711E90) is hooked: it runs every frame while the full map is shown and records `this`. No `MapUI.LateUpdate` for 3 frames = map closed (all per-map state dropped). The minimap's `MapUI.Awake` hook is not reused (one hook per address, and Awake is once per map UI scene load, not per open).

**Open settle (round 14).** Round 13 test: "map closes on first M press of the game in a save, have to reopen". Log of that open: the game's own open hitch (75 ms), then one 37 ms frame of this module (first icon scan of the save, 77 icon objects, mouse glyph search, hint clone); the reopen 0.6 s later (no first-time work) stayed open. The map closes on the **release** of its close input (`MapUI.Start`: `UIInputFocusRegistrar.BindCanceled(_closeInput, OnCloseInput)`, applied when the registrar gets focus; opening is `MapUIRoot.TryOpenMap` on `_openMapInput` *Performed*, the press), so a long frame right after the open, while M is still down, is the suspect. Now the icons and the key bar hint start `kOpenSettle` (0.35 s) after the open (the reveal still runs at once; right-clicks in that time are dropped). Not verified in game (the cause is inferred from the log). Diagnostics: an open shorter than 1 s logs `full map closed X s (N frames) after it opened (open #K this session; icons / hint had run | not started yet)`; perf detail scopes `map_tools.reveal`, `map_tools.icons (2 s)`, `map_tools.legend` show which step is slow.

## Reveal everything (`reveal_all`, default off)

RE: re/map.md (MapUIFogReveal, FogMapElement.SetRevealState: only caller RevealKnownZones; MapDirector.IsZoneHidden: only the zone-name LateUpdates call it; the static fog is never hidden by the game).

What the module does:

- Hook `SetRevealState`: `false` becomes `true` while the switch is on.
- Hook `IsZoneHidden`: `true` becomes `false` while the switch is on (zone names shown).
- On the live page: every Graphic with a `*FogOfWar*` shader outside every `FogMapElement` gets `Behaviour.enabled = false`; switched back on when the switch goes off or the map closes.
- Switch changed while the map is open: `RevealZonesInMap(MapUI._map)` re-runs the game's own pass.

**Persistence: none.** Nothing is written to the save or to the event record: `ShouldBeRevealed` / the zone queries are untouched, so the minimap, the collectibles tracker (map data nodes) and discovery stay real. With the switch off, the next map open (or at once if the map is open) shows the real fog.

**Map tabs.** User report: "Reveal doesn't let me go into the Labyrinth" (a new save: the Labyrinth's tab is not listed, and on the island page the Labyrinth is no zone area). The tabs are `MapViewModel._availableMaps`, filled once per view model from the `MapListConfiguration.GetAvailableMaps` lambda `<>c__DisplayClass1_0.<GetAvailableMaps>b__0(MapDefinition)` (RE: re/map.md, MapListConfiguration). The lambda is hooked: `false` becomes `true` while the switch is on, so every page gets a tab the next time the map opens (not on the open map). Counted in the hook, logged from the tick: `reveal: N map tab(s) listed that the save has not unlocked yet`. Display only like the rest.

## Icons on the full map

Source: `modules/minimap/api.h` `CollectPageIcons` (the minimap's own scanners, whole page, with this module's categories), so the icons need the minimap running and only fit the page of the player's zone: when the full map shows another map (tabs), they are hidden, except the remembered Nullifier walls ("Nullifier walls on other tabs"). Every 2 s while the map is open, and at once after a settings change.

Categories (`icon_*`, each with `size_*` in 1080p pixels, 12-64):

| setting | default | source |
|---|---|---|
| treasure pods | on | locked `TreasurePod`s (pod registry) |
| resource nodes | off | READY spawners with a live node |
| Nullifier walls | on | intact `DiscordantWall`s, also those of unloaded (proxied) regions, which are registered but inactive (they were missing before: `modules/wall_markers/NOTES.md`, "Inactive walls"); on another map tab the walls remembered per save (below) |
| placed gadgets (+ drone ports, teleporters/warp depots/links, decorations) | on (decorations off) | `GameModel.identifiablesByIdent` gadgets |
| undiscovered ancient teleporters / gordos / plort doors and landmarks | off | page markers the full map does not show yet (`CanBeShown` false) and are not done (popped gordo, solved door): spoilers |

Drawing: our own uGUI Images under a `SR2Mods.MapIcons` container that is a child of the live page (`MapUI._map`, a `Map` RectTransform), at local position 0 / scale 1, so icon positions are page-local (the same space as `Map.GetMapPosition` and the minimap's page copy). The game pans and zooms by moving / scaling the page, so the icons stay aligned whatever the zoom, and the map's mask clips them. Chosen over an ImGui overlay, which would have to re-derive the page's screen rect from canvas / camera every frame and would draw over the game's own popups.

- Constant screen size: each icon's local scale = (root canvas scale) / (page scale), recomputed per frame (two `TransformPoint`s each), applied only on a change > 0.5 %.
- `raycastTarget = false`: clicks and drags still reach the map.
- `icons_under_fog` (on): the container is inserted at the child index of the first direct child of the page that contains a `FogMapElement`, so the fog layer draws over the icons like over the map art. Off (or no fog on the page): before the marker containers (`Map._belowMarkersContainer` / `_staticMarkerContainer`). Logged: `icons: container on page '…' at child index N (…; fog layer '…' at F, markers '…' at M)`. ASSUMED: the fog layer's direct child holds only fog (true for RainbowIslandMap's `zone_fog_areas`); check that icons are not hidden under land art.

### Nullifier walls on other tabs

In-game test: the walls showed on the Labyrinth tab only while the player was in the Labyrinth (log: `the full map shows 'LabyrinthMap', the icons belong to 'MainWorldMap' - hidden on this map`). The walls exist only while the Labyrinth's scene group is loaded (all 17 register in `DiscordantWall._activeWalls` during its load and are destroyed when it unloads), and the game has nothing else about them: no per-wall save data (a wall is harmonized while a Nullifier gadget stands next to it), no map marker, no static list in code. So the module remembers them: every 3 s (map open or not) the live registry (`walls::Collect`, inactive walls included) is merged into a cache (position, intact flag; matched within 4 m in XZ), which is stored in the save's sidecar (`custom_upgrades` per-save value `map_tools.null_walls`, `x,y,z,intact;…`, written with the next game save) and read back when another save is loaded. On a map tab that is not the player's page, the cached intact walls are drawn with the minimap's wall sprite (`minimap::api::NullWallSprite`), projected with the view model's `_mapRect` / `_worldRect` (as the teleport's inverse) and clipped to `_fullMapRect`. One visit to the Labyrinth (with this build) fills the cache; a wall harmonized or opened again later shows its state from the last visit. Without `custom_upgrades` the cache lasts for the session only. **Own map only (round 14):** the walls were drawn on every tab that is not the player's page, also on Rainbow Island while in the Labyrinth (user: "the gray labyrinth walls show on the default map"). The cache now records the walls' map: the minimap's page `MapDefinition` name while the walls are live (re-read every poll), stored as a leading `@<map>;` entry of the sidecar value (older builds skip it: not a wall entry). Cached walls are drawn only when the shown map has that name; sidecars without the entry: maps named `*Labyrinth*`. Logs: `Nullifier walls belong to map '…' (was '…')`, `Nullifier walls: N new, C changed, T remembered (kept in the save's sidecar with the next save)`, `Nullifier walls: N cached in the loaded save (map '…')`, `icons: S of I cached intact Nullifier wall(s) on 'LabyrinthMap' (T remembered)`.

## Right-click teleport (`rmb_teleport`, default off)

- Input: `MapClickPlaceMarker.IPointerClickHandler.OnPointerClick` (0x706AB0) is the map surface's click handler (left button = toggle waypoint; other buttons do nothing in the game). Hooked: a right click (`PointerEventData.button == 1`, `_isDragging` false) sets a flag; the frame callback handles it. So a right click on a map button / panel does nothing.
- Cursor page point: `MapUI.LateUpdate` uses `-MapViewModel.CursorPosition` = `-(_mapAnchor + _cursorOffset / _mapZoom)` as the page-local cursor (it feeds `TryFindZoneAt`). `_cursorOffset` is set by `MapPanZoomPointerControls.OnPointerMove` -> `SetViewportCursorPosition`. Must lie inside `_fullMapRect`.
- World point: inverse of `Map.GetMapPosition` (`map = mapMin + (world - worldMin) * mapSize / worldSize`, the view model's `_mapRect` / `_worldRect` = the page anchors, `Map.GetMapArea` / `GetWorldArea`). Note: the game's own waypoint code (`MapViewModel.ToggleNavigationMarkerAtCursorPos`, 0x72BF80) puts the waypoint at `-(worldMin + (CursorPosition - mapMin) * k)`, which equals ours only for pages whose anchors have no offset (RainbowIslandMap: scale 1, offset 0). Check the "teleported ... (map point ...)" log line against where you clicked on other maps.
- Targets: the clicked zone is `MapUI.TryFindZoneAt` at the UI-world point of the click (`ZoneDetectionArea._zoneMapData`). The view model is bound to the tab shown, so its rects give the projection of whichever map page is open (other zones' tabs work the same way).
  - **Same zone** (the page is the map of the player's zone, and the click is in the player's zone area or outside every area, e.g. the sea next to the island) or another zone of the **same scene group** (e.g. The Conservatory from Rainbow Fields, see "Cross-zone travel"): in-scene teleport onto the ground (below).
  - **Another zone** (another area on the player's map, or any zone on another tab): refused with the fail cue only if the click is outside every zone area of a foreign page, or the zone is **not discovered yet** (`MapDirector.IsZoneHidden(ZoneMapData)` called past our own hook: never entered and not unlocked on the map by default), or no route into it exists. Otherwise the game's own zone-to-zone travel runs (next section).
  - **Undiscovered zones with "Reveal everything" on** are allowed (log `'<zone>' is not discovered yet - allowed, Reveal everything is on`): the switch already shows them, and arriving is what walking through the gate would do (the zone counts as entered from then on; gates such as the Powderfall Bluffs plort door stay as they are, the map teleport gets the player out again). **The Grey Labyrinth and The Sanctuary too** (round 3: the user asked for it and accepts the story risk; the Sanctuary is otherwise reached only at the end of the Labyrinth's story, scripted `TeleporterSanctuaryDestination` / boat ride). The log line adds `(a story zone: arriving early may skip parts of the story)`, and the Reveal tooltip says so. Without the switch: refused as before.
- **Fog (Reveal off).** User report (round 6): "Reveal off allows me to teleport to clouded areas". The zone test above only asks whether the zone was ever entered; the map's clouds are per fog area (`FogMapElement`, revealed by map data nodes, not by visiting). Every click with the switch off first asks the live page (`FogAt`).
  - **Round 7: "says the spot is not on my map yet, even when it clearly is", "for every area".** The log (19:26-19:30) had `20 fog area(s): 20 fogged, 0 revealed` from `ShouldBeRevealed`, and the minimap and the collectibles tracker agree (`0/20 areas revealed`, `Nodes 0/2` in every zone): the save has no map data node yet, so the state was right. The shape was wrong: the round-6 test took each fogged image's **rect** as the cloud. The fog images are SDF sprites (`map_fog_fields1_sdf` etc., 256 px, not CPU-readable) that the fog shader cuts at a threshold; the rects are far larger than the clouds (`map_fog_fields1` is a 984 x 984 page-unit rect around a cloud that covers maybe a third of it), so every click near the Conservatory (484, 326) was "under fog area 'map_fog_fields1'" while the map showed it clear.
  - Now: a fogged area's image (and every static fog image) is tested at the clicked point with its **read-back SDF and the fog shader's own threshold**. The sprite's texture is drawn into a temporary 128 px linear RenderTexture (`RenderTexture.GetTemporary`, `Graphics.Blit`: sampled as the shader samples it, sRGB or not) and copied back (`Texture2D(128, 128, RGBA32, no mips, linear)`, `ReadPixels`, `GetPixels32`, red channel), once per sprite per map open and only for images whose rect holds the click; the copies are released / destroyed at once. The point's UV = its position in the image rect (`InverseTransformPoint`; `preserveAspect` honoured), then the sprite's part of its texture; bilinear sample = SDF `s`.
  - The threshold is the fog shader's own (formula and the `FogOfWar` material values: RE: re/map.md, "Fog shaders"), material values read per material with `Material.GetFloat` (the known values as defaults). At a fogged area's full CanvasGroup alpha the radial reveal term is 1. The noise is not known per pixel, so the test takes `n = 0` (its mean): a cloud where `level >= 0.5`, i.e. `s >= ~0.24`. With the noise the drawn edge moves (`s` 0.1-0.4 for `n` = +-0.5), so a click right at a cloud's edge can go either way; the log says "near the cloud's edge" when level < 1.25.
  - A revealed area draws nothing (its alpha is 0), so it no longer matters whether a revealed neighbour's rect covers the point. If the art cannot be read (read back unresolved or failed, or it came back empty), that image's rect decides as before and the log line says so.
  - Offline check (UnityPy, the prefab's `map_fog_fields1` placement assumed at the page origin): the Conservatory clicks of the round-7 log come out clear or at the edge (e.g. (513, 305) level 0.17, (737, 307) outside the cloud), the middle of Rainbow Fields (303, 354) under the cloud (level 5).
  - One line per click with the inputs: `fog check at map point (x, y) = world (x, z), zone '<zone>': UNDER fog area '<name>' (cloud level L >= 0.50, SDF S[, near the cloud's edge]) | clear (strongest cloud here: '<name>': cloud level L < 0.50, SDF S) | clear (no fogged cloud image here); N fog area(s): F fogged, R revealed, U unknown (state from ShouldBeRevealed)[, N fogged with no fog-shader art, not clouds (<names>)], S static fog image(s); T image(s) tested by their art[, K by their rect (<why>)]`, and once per sprite per map open `fog art '<sprite>' read | not readable: <why> (128 px read back, peak SDF P, sprite part of its texture (...))`. Refused: `teleport refused: (x, z) is under the map's fog (...)`, pop-up "that spot is not on your map yet".
  - The fallback the task allowed ("the zone's map is unlocked", per map data node) is not used: the per-pixel test is possible, and per zone would also have refused the Conservatory on this save (no node in any zone). ASSUMED (not testable offline): that `Graphics.Blit` + `ReadPixels` work from the frame callback under HDRP (the sandbox's prefab icons read back a camera render the same way) and keep the texture's orientation (row 0 = v 0); a flipped or empty read back would show in the log as clicks clear in the middle of a cloud / `read back empty`.
  - **Round 8: still "same as before" by the Conservatory.** The log (22:02:44-47, Reveal off, 19 fogged / 1 revealed): every Conservatory click ((511, 321), (536, 430), (587, 292), (459, 297)) was `UNDER fog area 'zone_link_strandmain' (its image rect: the art is not readable, no sprite)`, while the real clouds were read fine (`fog art 'map_fog_fields1_sdf' read`, `map_fog_strand1_sdf read`, peak SDF 1.00) and tested clear at those points (they come first in the page order and did not decide). The SDF test was right; the culprit was a **zone link**: `zone_links/zone_link_*` (strandmain, gorgemain, bluffsmain, strandrear, gorgerear, bluffsrear) carry a `FogMapElement` as well (they fade in on their reveal event), but their graphics are a dotted portal line (`PortalLineSpline/PortalLineTest`, a custom Graphic, no sprite) and portal icons, all with the default UI material. A hidden link draws nothing; its line's rect spans from the Conservatory to the Strand, and "no sprite" sent it to the rect fallback.
  - Now only **fog-shader art** (material shader name with `FogOfWar`, enabled) of a fogged area is tested, as the static fog already was; a fogged area without such art is not a cloud (the old "no art at all: its own rect" fallback is gone too: it would have caught `zone_link_labyrinth*`). The click line lists them: `…, N fogged with no fog-shader art, not clouds (zone_link_strandmain, …)`. The rect fallback stays only for fog-shader images whose SDF cannot be read back.
- Never while the player is knocked out or a scene load runs (`ground_teleport::PlayerUnavailable`): refused without the cue.
- Ground and teleport: the shared ground teleport (next section), started at once; the map closes right after (`UIDisplayManager.Instance.CloseDisplayByObjectInHierarchy(MapUI)`, what `DroneUIDisplay.CloseThisDisplay` does). The result (landed, or no safe spot: the player stays where he is) comes as a pop-up, at once for a loaded spot or after up to ~6 s for a far one.
- Refused clicks play the map's own `_failedPlaceWaypointCue` (`UIAudioCueHandle.PlayAudioCue`, NO_WARNING), log `teleport refused: <reason>` and show the reason in the key bar hint (map open) or a pop-up (map closed). The cue is for targets that cannot be reached: outside the page / every zone, not discovered, no route. "No ground" is known only after the map closed: pop-up and log line, no cue.
- A click over the slime sea, lava or another kill volume is refused ("no safe spot there"); in the Grey Labyrinth the floor under a roof is taken (next section).
- The map gives only (x, z): there is no height to prefer the surface nearest to the clicked point, so the floor pick decides from the geometry and the collider names alone.

### Finding the ground (`ground_teleport.h/.cpp`, shared with the sandbox's "Teleport to waypoint")

**Streaming** (in-game test, 1.3.0): far spots used to fail with "no ground". The world is streamed by regions and regions away from the player are proxied (colliders deactivated), so a raycast over a far spot has nothing to hit. RE: re/world.md (RegionLoader / Region).

**The knock-out crash** (in-game test, Player.log + sr2mods.log, 15:10:35): a right click on the far west of Ember Valley (-1129, 485) parked the player (old design: at his own height y 11, beside the target) inside the area's fall-through kill volume: `Fallthrough destroying: PlayerControllerKCC` (`KillOnTrigger.OnTriggerEnter` -> `DeathHandler.Kill` -> `PlayerDeathHandler.OnDeath` -> `ResetPlayer`) 50 ms later. The helper did not notice and kept re-parking him every 0.5 s for 3.6 s with `TeleportablePlayer.TeleportTo`, which also calls `PlayerModel.SetCurrentSceneGroup(group)` (IDA 0x54EC90): during the respawn load into the ranch it kept setting the player's scene group back to RumblingGorge, and its own "scene changed" check read that same group. The respawn load then failed (`Error while populating Land Plot Model`, a `NullReferenceException` in `StorageUpgrader.Apply` / `AmmoSlotManager`, then the `ErrorHandling` scene: "An error occurred, return to main menu"). The same cross-zone respawn without our teleports (the third knock-out of that log, from the Labyrinth) loaded fine, so the interference is the most likely cause; the NRE itself is the game's. Also: `TeleportTo` without a rotation keeps the controller's velocity, so every re-park started with the speed of the last fall.

What the helper does now (main thread, Resolver::Invoke for every game call; TeleportTo direct under GuardedCallEx because of its `Nullable<Vector3>`):

1. Refused while the player is **knocked out** (`PlayerDeathHandler._isPlayerDead`, a `ScriptedBool`, `get_Value`) or a **scene load** runs (`SceneLoader.IsSceneLoadInProgress`; the knock-out is tested first, a respawn into another zone is also a load). Checked again every frame while waiting and right before landing: the request is dropped and the player is not moved (`teleport to (x, z) dropped after T s: the player is knocked out - the player was not moved`). `PlayerUnavailable()` is exported for map_tools (refuses clicks, drops a zone travel when the player is knocked out).
2. Player: `SceneContextUtility.TryGetSceneContext` -> `SceneContext.Player` -> its `TeleportablePlayer`, its `SceneGroup`, position and `Transform.eulerAngles`.
3. **The target is loaded in place, the player is not moved**: `RegionLoader._regionReg.GetRegions(group)` (a new `List<Region>`), every region whose `Bounds` (XZ) come within 24 m of the column gets `Region.AddNonProxiedReference()` (IDA 0x8F5D00: the game's own reference count; the first reference runs `Unproxy`: `Root.SetActive(true)` + adjuncts). Released with `RemoveNonProxiedReference()` (0x8F6B40: `Proxy` at 0) 1.5 s after landing (the RegionLoader has its own references by then), at once on a refusal or abort. Nothing to load (near, or no region there): the floor is picked at once.
4. Floor pick (`PickFloor`): rays from y 2000 straight down, layer mask = `Layers.GetLayersCollidedWith(player layer)` (the game's collision matrix: what the player can stand on; the old mask "all but Ignore Raycast" landed on `Depth Only Quad`, a render helper the player fell through in the Labyrinth test), triggers ignored, the player's own colliders skipped. Every upward-facing surface below the column is collected (the next ray starts 5 cm under the last hit; one-sided mesh colliders / terrain are not hit from inside), up to 16. A surface is a valid floor when it is walkable (normal.y >= 0.7), has 2.6 m of headroom (upward ray), no **hazard trigger** within 1 m around a point 1 m above it (`Physics.OverlapSphere`, all layers, triggers included; a collider whose object or parent has `KillOnTrigger` (fall-through kill volumes, the slime sea), `KillOnTriggerCloudOcean`, `LavaVolume` or `DamagePlayerOnEnterTrigger`), and is not sealed in (one of 8 horizontal 4 m rays 1 m above it is free). Render helpers are looked through (names with `VISBLOCKER` or `Depth Only`). The top surface wins, unless it is a **roof over an indoor floor** (below, round 3); then go down (repeatedly, stacked roofs too). The top surface refused and no roof case: refused with its reason ("hazard: KillOnTrigger on '..'", "too steep", ...). The game has no placement helper of its own for this (its teleports go to fixed `TeleporterNode`s, respawns to fixed wake-up points).
5. Waiting (regions were loaded): from 0.3 s on, the pick runs every 0.1 s (it was every frame: one frame took 73 ms in the round-2 test, `frame:ground_teleport max 73.60`); it counts when two picks at least 0.2 s apart agree within 0.5 m. Then `TeleportTo(floor + 0.6 m, group, current rotation, overlayEnabled true)`: with a rotation the game also zeroes the controller's `BaseVelocity`. Nothing valid after 6 s: refused (the player never moved).
6. **Fall check**: 1.5 s after landing, a player more than 8 m below the landing point (same scene group, not knocked out) is put back where the teleport started (after a zone change: the arrival teleporter). Log: WARN `the player fell through after landing at (…): at y Y 1.5 s later - put back at the start point (…)`. A new teleport cancels the check.
7. One teleport at a time (`Busy`); a scene change or the player going away aborts it.

#### Roofs and floors (round 3)

User reports: "Spawned me on the roof of the same place" (Grey Labyrinth) and "teleported me under the map in some cases" (going to the Conservatory).

- The Labyrinth: no Labyrinth landing with the round-2 pick is in the logs (16:06 session, build 590ef8b, a new save without the Labyrinth: that is the "Reveal doesn't let me go into the Labyrinth" report). The only Labyrinth roof landing is from the round-1 build (15:16:01, build 1aacffc, no roof rule yet): `landed at (974.4, 127.0, -1189.7) on 'caveRoof01 (1)'`. A cave roof can be far thicker than 6 m, so the thin-slab rule alone would have kept it there.
- Under the map (16:35:40): `landed at (552.7, 11.0, 311.2) on 'caveRoof01 (6)' …; 'greenhouseRoof_03 (1)' at y 51.5 is a roof over 'greenhouseHangingPlanter_02' at y 32.6; 'greenhouseHangingPlanter_02' at y 32.6 is a roof over 'areaFieldsPlane03 (33)' at y 17.1; 'areaFieldsPlane03 (33)' at y 17.1 is a roof over 'caveRoof01 (6)' at y 10.4`. The ground plane `areaFieldsPlane03` is one-sided: an upward ray from below does not hit it (no backfaces), so the old rule took "no underside found" as a zero-thickness slab and went on down to the top of a rock under the ground. The player teleported out 13 s later from (552.7, 10.4, 311.2). Not a loading or scene group problem: all four surfaces were there, the pick was stable.

The rule now (`PickFloor` / `RoofOver` / `CoverOf`), for the surface `a` above and a valid floor `b` below it:

- `b` must be **indoors**: a ceiling straight above it, at most at `a`'s height, at least 2.6 m up. Two upward rays: the normal one (front faces) and one with `Physics.queriesHitBackfaces` on (switched on for the one ray and restored at once; main thread, nothing else queries in between). If the nearest face above is seen **from behind** (the backface ray hits nearer than the normal one) and is not a roof by name, `b` is **buried** (inside the level geometry or under a one-sided ground plane): not a floor, look further down. A roof by name seen from behind (a one-sided roof) counts as the ceiling.
- `a` must be a **thin slab** (that ceiling within 6 m below its top) **or a roof by name**: `roof`, `glass`, `ceiling`, `canopy` in the collider name (`caveRoof01`, `greenhouseRoof_03`, `glass` in the logs), at any thickness.
- A surface that is a roof by name is never taken as the floor under a roof (`a roof by name, not a floor under a roof`).
- With the new rule the 16:35:40 case stops at `areaFieldsPlane03` (y 17.1): `caveRoof01 (6)` is a roof by name, and buried under the plane's back anyway.
- If the top surface is a roof by name and no indoor floor qualifies, the player lands on it, and the landing line says so (`landing on '…' (a roof by name): no indoor floor found below it`).

Every landing and refusal now also logs every surface of the column: `surfaces below (x, z), top down: 'greenhouseRoof_03 (1)' y 51.5 ok; 'areaFieldsPlane03 (33)' y 17.1 ok; 'caveRoof01 (6)' y 10.4 a roof by name, …; '…' y … under the back of '…' at y … (inside the level geometry); '…' (looked through); '…' (not checked)`. Use it for the next Labyrinth test.

Logs (`ground_teleport[<module>]: ...`): `target (x, z) is N m away: L of P region(s) there loaded on the spot, the player stays at (...) meanwhile; RegionLoader ...`, `landed at (...) on '<collider>' (layer N) from (...), N m, L of P region(s) loaded first, T s, C floor check(s), R ray(s); '<roof>' at y .. is a roof over '<floor>' at y ..`, `not teleported to (x, z): <why>. rays from y 2000 down 4000 m, layer mask 0x.. ### Cross-zone travel

- The game's teleporters into another scene group: `TeleportNetwork.TeleportToDestinationImpl` (RE: re/map.md, TeleportNetwork: an unregistered node means a scene load, after which the player is placed at the node). `quick_travel` hooks this same method (it only shortens the loading screen's padding), so those speed-ups apply here too.
- Zone -> scene groups: `ZoneSceneGroupMapping._mappings` (`List<ZoneMapping>`, struct `{ZoneDefinition Zone, SceneGroup[] SceneGroups, SceneGroupList SceneGroupListAsset}`; `SceneGroupList` is a `ListAsset<SceneGroup>`, its `items`), every entry of the zone. **"No way into The Conservatory"** (test log: `none of the 37 teleport destinations leads into it`): the old search went the other way, `ZoneSceneGroupMapping.TryGetValue(destination group) == zone`. The Conservatory (the ranch) and Rainbow Fields are one scene group, `ConservatoryFields` (you walk between them without a load; the log's Rainbow Fields travel arrived in `ConservatoryFields` at `TeleporterFieldsToGorgeMain`), and `TryGetValue` answers only the first zone of a group, so no destination ever "led into" the Conservatory. Now: zone -> its groups; a click on a zone whose groups include the player's current group is an in-scene teleport (the Conservatory from Rainbow Fields); otherwise the route is a destination that arrives in one of its groups (the Conservatory from Ember Valley: the Rainbow Fields arrival node, then the ground teleport into the Conservatory). **Still "No way into The Conservatory" after that** (test log: `none of the 37 teleport destinations leads into it (no scene group mapping entry for the zone)`, from Rainbow Fields): the mapping has no entry for the Conservatory at all (the once-per-session route log lists six zones, Rainbow Fields with `ConservatoryFields`), so neither the in-scene test nor the route search could match it, from any zone. Now a zone without a mapping entry whose `ZoneDefinition._isRanchZone` is set belongs to `SceneLoader.DefaultGameplaySceneGroup` (the ranch's group, `ConservatoryFields`; logged once: `zone '<name>' has no scene group mapping entry; it is the ranch zone, so its scene group is the default gameplay group '…'`): from Rainbow Fields an in-scene teleport, from every other zone the travel into a `ConservatoryFields` arrival node, then the ground teleport into the Conservatory. Other zones without a mapping entry fall back to `TryGetValue`.
- Route (which node): the static teleport network `TeleportNetwork._networkDefinition` (`StaticTeleportNetworkDefinition` = `ListAsset<TeleportSystemDefinition>.items`), every `DestinationNodes` entry `{DestinationNode (TeleporterNodeDefinition, get_NodeId), DestinationSceneGroup}` whose group belongs to the zone. These are the nodes the game's own zone-to-zone teleporters arrive at, so they are registered once their scene group is loaded. Nodes named `*OneWay*` are taken only if nothing else arrives there: the test's Grey Labyrinth travel into `TeleporterOneWayLabyrinthHub` loaded the Labyrinth (its walls registered) and then put the player back in the start zone. The mapping asset is found with one `Resources.FindObjectsOfTypeAll` (the map UI's drone menu references it, so it is loaded while the map is open), re-tried at most every 30 s.
- Every zone's arrival point is logged once per session at the first cross-zone click: `route: '<zone>' (scene groups a, b): arrival '<node>' in '<group>'; other arrivals: …` or `… no arrival (<why>)`. The home / ranch has no teleporter of its own in the network; it is reached through its scene group, as above.
- After the click the map closes and the module waits (every 0.5 s): `SceneLoader.IsSceneLoadInProgress` false and the player in the destination group (or any other group of the zone), one more step to settle, then the shared ground teleport at the clicked point (it loads the spot's area itself; no ground: the player stays at the arrival node, pop-up "Teleported to <zone> (spot not loaded, at the teleporter)"). A load that ends with the player back in the start group is logged as a failed travel (`travel to '<zone>' failed: the load ended with the player back in '…' (arrival node '…' in '…' not reached)`). Given up after 90 s without arriving. One travel at a time (a click meanwhile is refused without the cue).
- The player knocked out while travelling (`PlayerUnavailable` knock-out): the travel is dropped (`travel to '<zone>' dropped: the player is knocked out (the game's respawn takes over)`), no ground teleport after the respawn.
- Logs: `travelling to '<zone>' (scene group '…', arrival node '…'; other arrivals: …), then to (x, z)`, `arrived and teleported from (…) to (…) (zone '…', area loaded first in T s), N s after the click` / `arrived in '<zone>', but not teleported to … - staying at the arrival point`.

## Fault policy

- Detours: the original is always called; the module's logic (record a pointer, flip `isRevealed` / the hidden result, set the click flag) runs in a `DetourGuard`. No IL2CPP calls inside hooks.
- Frame callback: `core::Try` + `ugui::GuardNative`; managed exceptions of single game calls are contained; a native fault disables the module for the session (references abandoned, no teardown calls). A frozen minimap (shared `ugui` bindings) stops this module too.
- No scene scans: the player (`TeleportablePlayer`) is found once with `FindFirstObjectByType` when a teleport needs it; the page's children are walked once per map open (static fog, container placement) and the legend once per open; the mouse glyph search is one `FindObjectsOfTypeAll` per map open until found; the ground teleport finds the `SceneLoader` once (re-tried at most every 5 s).
